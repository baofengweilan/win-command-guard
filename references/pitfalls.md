## 事故 1：.bat 的"幽灵碎行"（→ 闸二）

**症状**：agent 生成的 `.bat` 一运行就报 `'rem' 不是内部或外部命令`、`'ist' 不是内部或外部命令`——
命令像被随机切成了两半。

**根因**（两个，都实测复现）：
1. cmd 按**代码页（ANSI/GBK）**逐行解析 bat。文件是 UTF-8 时，中文注释的字节流被 GBK
   重新切分，行边界错乱 → 碎行。
2. cmd 对 **LF-only** 换行的 bat 会"串行解析"，把下一行残片当独立命令 → `'ist'` 这类
   半截词报错。

**修法**：.bat/.cmd 必须 **GBK(ANSI) 可编码 + 纯 CRLF**。
**护栏动作**：Write/Edit 写 `.bat|.cmd` 时预检这两项，违规即拦并告知改法。

---

## 事故 2：URL 被悄悄截断（→ 闸三）

**症状**：带查询串的下载/请求命令（`https://x.com/api?a=1&b=2`）行为诡异——
返回不对、参数丢失，且没有任何报错。

**根因**：命令最终由外层 **cmd** 派发。cmd 只认**双引号**内的 `&`；pwsh 的单引号
对 cmd 不存在。于是 `&b=2` 被当成"前一条命令结束后再执行 b=2"，URL 查询串被截断。

**修法**：URL 写进 pwsh 单引号串（外层双引号已保护），或先落 `.ps1` 再 `-File` 执行。
**护栏动作**：命令含 URL 且 `&` 裸露在双引号外 → 拦。

---

## 事故 3：护栏自己静默失效（工程教训）

**症状**：护栏上线后"完全不拦"。日志无异常。

**根因**：脚本里用了 `$input` 做变量名——它是 PowerShell **自动变量**（管道输入枚举器），
stdin 被管道喂入时已被绑定，赋值**静默失败**，导致命令变量恒为 null、全部规则短路放行。

**修法**：改用 `$toolInput`；此坑已写进脚本注释，防止回归。

---

## 事故 4：转义双引号让两层 shell"分叉"（→ 闸四）

**症状**：
- `python -c "print(\"hi\")"` 输出被吞 / 报语法错误；
- `pwsh -Command "..." | Select-Object Name` 报 `'Select-Object' 不是内部或外部命令`。

**根因**：cmd 解析 `"` 只认"翻转"、反斜杠是字面量。内层一旦出现 `\"`，cmd 的引号状态
就和 pwsh 的参数解析**分叉**；"裸露区"里的 `| & %` 归 cmd 管，被当成 cmd 自己的语法执行。

**修法**：内层字符串一律 pwsh 单引号；要双引号字面量 / JSON / 多层嵌套 → 先落 `.ps1` 再
`-File` 执行；整条管道写进引号内。
**护栏动作**：内层 `\"` / `""`、收尾引号外挂 `|` → 拦。

---

## 事故 5：中文乱码的"真凶"是 -NoProfile（编码规范）

**症状**：Python 脚本输出的中文路径/关键词满屏乱码（"汽修二班"→"姹戒慨浜岀彮"），
而 PowerShell 自己打印的中文完全正常。

**根因**（对照实验证实）：
- Python 脚本 `sys.stdout.reconfigure(encoding='utf-8')` → 输出 **UTF-8 字节**；
- PowerShell 用 `[Console]::OutputEncoding` 解码子进程输出，中文 Windows 默认 **GB2312**；
- UTF-8 被当 GBK 读 → 乱码。用户 profile 里本有 UTF-8 修正，但命令带了 **`-NoProfile`**
  把它绕过去了。

**修法**：
1. profile 统一 UTF-8（`chcp 65001` + 三个 Encoding 设置）；
2. 涉及中文输出的命令**不要 `-NoProfile`**；
3. 启动脚本顶部自带 `[Console]::OutputEncoding = UTF8` 兜底。

**护栏动作**：闸一的拦截提示里附带这句提醒，从源头纠正习惯。

**演进（2026-11-07）**：标准改法模板升级为**内联 UTF-8**——`[Console]::OutputEncoding=UTF8` 直接写进
`pwsh -NoProfile -Command "…"` 模板，`-NoProfile` 从此恒安全；原先"中文输出别用 -NoProfile"的例外提醒删除。
少一个需要现场判断的分支，就少一种乱码返工。

## 事故 6：PATH shim 冒充 powershell，游戏安装器"静默死亡"（2026-11-07）

**症状**：Steam 里点"开始游戏"，引导进程起来 3 秒后悄悄退出（退出码 -2），无崩溃转储、无系统拦截——
是引导器"主动放弃"，不是被杀。重试多次同样结果。

**根因**：机器 PATH 里曾有一个把 `powershell` 重定向到 pwsh 7 的自装 shim（本为让 AI 一律用 7）。
游戏引导器安装反作弊服务时用 `powershell` 查询服务状态——shim 不认 5.1 的调用方式，吐出的是
pwsh 的帮助文本；引导器解析到空结果 → 误判"服务停不下来" → 轮询失败 → 放弃退出。
**系统组件对 `powershell` 的期待是真 5.1；PATH 是全机器共享的，任何全局改名都会波及它们。**

**修法（分层，各取所需）**：
1. 禁用 shim，`powershell` 名字归还系统——安装器/引导器拿到它们期望的 5.1；
2. AI 侧用 7 靠**护栏强制显式 `pwsh`**（本技能的闸一），不靠改系统的名字；
3. 中文输出用标准模板内联 UTF-8，与哪个 shell、用不用 profile 都无关。

**原则：改调用方，不改系统的名字。** AI 兼容性问题的正解是"让 AI 显式说 7"，
而不是"把系统的 5.1 改名叫 7"——后者等于在全机器范围内给所有安装器埋雷，COD 只是第一个踩上的。

## 护栏生效实录（拦截 → 给规则 → 一次通过）

护栏的价值不只"拦住"，更在"拦住之后 agent 能一次改对"。以下为实跑记录：

- **2026-11-09 · 闸四（4a）× curl 下载命令**：命令内层用 `\"` 转义引号，被闸四拦截；
  拦截信息给出的规矩（内层一律 pwsh 单引号、禁 `\"`）足以定位问题——第二版改用
  **单引号 + Join-Path 拼路径**，一次通过，零额外往返。
- 结论：**拦截 → 给规则 → 照做即过**，这条反馈闭环是自洽的；"拦截多花一轮"换来的是
  命令从此落进正确写法，比放任错误写法滑进报错循环便宜得多。
- 已沉淀：路径类参数一律 `Join-Path` 拼、URL/参数整体单引号（已写进闸四的拦截提示）。
